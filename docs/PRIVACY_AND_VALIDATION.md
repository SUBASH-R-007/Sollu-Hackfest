# Privacy, fragmented communication and validation review

**Sentence-only cloud opt-in (2026-09-28):** the local operator enabled `ALLOW_CLOUD_AI=1` at the user's request; the checked-in default remains blocked. Settings → Sentence engine now has a separate **Allow cloud sentence APIs on this device** permission. It allows sentence text without enabling online microphone input, remote voices or external camera models. Provider-specific text-sharing consent remains required. The permission stores only an allowed/blocked token, revokes pending requests across same-origin tabs, is checked again at dispatch, and is reset by restoring local privacy protection or erasing device data. Missing permission preserves previously explicit online-mode behavior; malformed/unreadable permission fails closed. No API key or patient content is stored in this token, and no real provider request was made to enable the setting.

## Implemented privacy architecture

The default sentence path is the bundled controlled vocabulary. Optional Ollama runs at a validated loopback endpoint on the Sollu server computer. Model installation is separate; the daemon must itself be configured for local-only operation (`OLLAMA_NO_CLOUD=1`) and its software/model behaviour reviewed. No model or speech language pack is downloaded by this change.

The online app still sends bounded sentence requests to its same-origin Sollu server. On localhost this is the same computer. A future remote host would be another data processor; this mode does not make that server on-device or exempt it from review. Explicitly paired caregiver messages and user-initiated downloads also remain possible. “Local-only” describes the processing policy, not a claim that every action is network-free.

**Server policy:** cloud AI is blocked unless the server operator deliberately sets `ALLOW_CLOUD_AI=1`. Environment keys, a previously saved cloud selection, device consent or a forged selection cannot bypass the default. Settings expose the effective policy and disabled provider choices. The actual cloud adapter also checks the policy. The intent request's `localOnly` flag defaults true; when true, a saved cloud provider becomes the catalog, while loopback Ollama is still allowed. Redirects to external endpoints are rejected. This preserves existing adapter code for a future approved deployment, but OpenAI is not required or active by default.

**Device policy:** local-only processing starts enabled, including on existing installations missing this setting. It limits browser output to voices marked local, requires supported on-device recognition, and blocks external object-model downloads. Typing, Topics, local recording/replay, manual transcript review and AAC remain available. Unsupported recognition does not silently contact a browser vendor. Turning off device protection is an explicit caregiver setting; it does not override the server's cloud policy or provider-sharing consent.

Protection changes cancel pending output/input and inference. Same-origin tabs share a small policy latch with no patient content, so a stale tab cannot silently retain broader transfer permission. An unrelated settings save must not overwrite a newer privacy decision. Browser/OS extensions, a compromised machine and software outside Sollu are outside this application boundary.

**Speech evidence:** audio/video capture remains local and separately consented. Saved clips are reviewed using a transcript entered while listening; the live browser recognizer performs another attempt. No recording is uploaded to the sentence engine or claimed to be model training. Capture release, cancellation and two-minute/size limits remain enforced.

**Reports:** passphrase-encrypted JSON export/import uses authenticated AES-256-GCM with fresh salt/nonce and PBKDF2-SHA256 (600,000 iterations). The wrapper contains cryptographic parameters and ciphertext, not participant names or transcript text. Size/version/parameter limits precede decryption; decrypted data still passes normal report validation. A wrong passphrase or altered ciphertext fails closed. Passphrases are not saved. This is file protection, not signer authentication. Share the passphrase separately through an agreed channel; Sollu does not send either file or passphrase.

Plain JSON/CSV remains an explicit unencrypted export option. Individual audio/video clips remain separate, consented, **unencrypted downloads**; encrypted report export does not include them. Redacted reports still contain potentially identifying dates, participant codes and other observations. Imports are read-only, unverified local snapshots and cannot resolve local recordings from another patient.

| Retention/deletion | Explicit record/media deletion and device erase; exports remain independent | Agreed retention schedule, backup recovery, deletion verification and incident procedures |

| Regulatory/clinical | Research-informed prototype, not cleared or clinically validated | Intended-use assessment, applicable regulatory path, clinical/ethics review and validation with representative users |

No real patient information should be used to claim a clinic-ready demonstration of these gaps. Use fictional fixtures for jury demonstrations. Do not claim that local-only means HIPAA-compliant, anonymous, fully encrypted, or CDSCO-approved.

## Broken words: supported behavior and limits

The controlled engine now proposes conservative repairs for repeated/stuttered words, explicitly split syllables and uniquely supported everyday prefixes in English, Tanglish and Tamil. Examples in regression tests include `w-w-water`, `wa-ter`, `me want wate`, `th-thanni` and `தண்-ணீர்`. The original fragment is retained. Confirmation exposes the proposed interpretation before the person chooses a sentence.

Short ambiguous prefixes, competing interpretations, unknown qualifiers, clinical terms, quantities and body-side details cannot be guessed into a convenient sentence. Refusal is preserved. Explicit reviewed personal corrections take precedence, match whole tokens, respect language/place/listener scope and cannot chain into unreviewed substitutions. This is bounded assistance, not a promise that every broken phrase will be understood.

## Accuracy and rehabilitation metrics

- **Sentence text match:** existing token-edit score against a reviewed transcript; not pronunciation, intelligibility or recovery.
- **Target-word match:** aligned target-word matches divided by target-word occurrences in eligible reviewed records. Repeated target words count as separate opportunities. Omissions/substitutions use the same denominator. Extra transcript words are listed separately; they affect the sentence edit score but do not become invented target opportunities.
- **Coverage:** show missing target/transcript, unreviewed records, AAC exclusions and eligible sample sizes. A redacted import cannot recreate hidden word accuracy. Language and communication method remain explicit grouping/filter dimensions.
- **Words to practise:** reviewed transcript differences and person-marked words are distinct from free-communication corrections. A person can choose a word for practice without automatic recording or speech.
- **Weekly trends:** descriptive observations with denominators and comparable groups, not causal treatment effects. Small or missing samples are visible.
- **Understanding and efficiency:** maintain person/partner/reviewer reports, communication success denominator, unassessed counts, taps, composition-to-speech-start time, practice readiness time, effort and fatigue. Playback success alone is not communication success.

Personalization uses these reviewed choices and explicit correction mappings. No acoustic model is fine-tuned, no clinical scale is invented, and no automatic therapy dose is prescribed. ## Validation protocol before stronger claims

1. Define intended users, settings, languages, supported input methods, excluded uses and the claimed endpoint with qualified SLPs and regulatory/privacy reviewers.
2. Recruit with accessible consent and stage/condition-appropriate support. Predefine sample size and analysis with a qualified investigator; do not invent a clinically meaningful threshold from app logs.
3. Keep development phrases separate from held-out phrases/speakers. Include broken words, silence, repetitions, negation, names, quantities, code mixing, ambiguity, fatigue and AAC. Evaluate free catalog, personalized catalog and chosen local model separately.
4. Establish intended meaning with the person/partner. Measure supported interpretation, abstention/clarification, unsafe contradiction, top-choice acceptance and actual partner understanding; preserve original input and review disagreements. Report denominators and uncertainty.
5. For recognition, compare consented recordings with independent reviewed transcripts using appropriate word/character error measures. Evaluate acoustic models on unseen speakers/sessions and representative devices. Do not reuse a corrected target as an independent reference.
6. Measure audible start, taps and completed communication on physical devices; assess accessibility, fatigue and ability to refuse/repair. Progressive-condition success may be maintained participation, not an increasing speech score.
7. Only a separately designed clinical study can support treatment-benefit claims. Keep engineering tests, usability findings, clinician observations and clinical outcomes separate.
8. Perform a privacy/security review covering device compromise, cross-tab state, network capture, exports, consent revocation, deletion, backups, incident response and institutional/vendor responsibilities. Reassess whenever the deployment or model changes.

The implementation and automated evidence are engineering deliverables. Human, legal/regulatory and clinical acceptance remain pending until the responsible reviewers provide their actual findings.
