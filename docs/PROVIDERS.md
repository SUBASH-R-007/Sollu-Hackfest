Settings → Sentence engine adds **Allow cloud sentence APIs on this device**. This permission is independent from local microphone, voice and camera-download protection. Provider-specific sharing consent and credentials remain required. Request dispatch rechecks sentence permission after asynchronous device registration; revocation clears pending drafts across tabs. **Multiple sentence options (2026-09-28):** the contextual prompt requests two or three distinct grounded meanings when supported. Valid model drafts lead; already-validated prepared options can fill spare slots after the same semantic deduplication, negation and rejection checks. A specific input may still justify only one choice; an empty model clarification remains empty. This uses one provider request, without retrying just to fill the screen. The UI labels AI drafts and prepared options separately. Caregiver choice count controls initial display; **Show more options** reveals remaining validated choices without speech or another request. Hidden choices are not logged as seen or rejected until revealed.

The existing array schema already permits zero to three candidates. Rechecked the official [OpenAI structured-output guide](https://developers.openai.com/api/docs/guides/structured-outputs) and [Ollama structured-output guide](https://docs.ollama.com/capabilities/structured-outputs); no transport, provider, model, retention or privacy setting was changed. **Speech recognition chooser (2026-09-28):** Settings → General and Privacy now provide **Local · on this device** and **Google / browser online**. Local is the default even after the broad privacy switch is turned off. Online input requires an explicit browser-specific choice; local-only protection overrides it and restoring protection resets the choice to local. The preference contains no audio/content, lives in this browser's localStorage, is not restored by personal-data backups, and is reset by device erase. Changes stop recognition across same-origin tabs without restarting a microphone. Both Speak and rehabilitation live transcription use the same policy.

## Configuring a sentence engine

In caregiver **Settings → Sentence engine**, select the provider, model and maximum wait. For a cloud provider, acknowledge sharing and enter a key. **Save** only updates settings; **Test connection** makes one synthetic request and may use paid quota. It sends no patient content and does not establish sentence quality. No provider account is created automatically.

Keys entered in this form travel to the local Sollu server and remain only in its memory, scoped to the authenticated browser/device token. They are never returned to the browser, written to IndexedDB, included in backups, or logged. Settings and session keys expire after 12 hours without settings/intent activity, server restart, or bounded-session eviction (maximum 1,000 devices). Clearing browser data loses the device token but does not immediately clear the server's old entry; expiry/restart clears it. A caregiver PIN protects the local UI, not the server API independently of device ownership.

**Forget session key** removes that provider's in-memory key without changing the active provider or granting cloud permission. An environment key becomes available again if configured. To remove an environment key, edit the server environment and restart. Switching to **Free vocabulary** stops new cloud intent requests; other saved session keys remain until forgotten or expired. No automatic failover to a different cloud company occurs.

For server configuration, use `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` or `GROQ_API_KEY` in an untracked `.env`. `LLM_PROVIDER`/`LLM_MODEL` choose environment defaults; `MOCK_PROVIDERS=1` keeps the default free path. Even with a cloud environment default and key, each device starts with Free vocabulary until cloud sharing is explicitly enabled. Ollama uses `OLLAMA_BASE_URL` and `OLLAMA_MODEL`. No keys use a `VITE_` prefix. For a shared server, use HTTPS, `ACCESS_CODE`, and a strong `SERVER_SECRET`; the current localhost flow needs no hosting.

Model IDs are editable because entitlement and availability differ by account. These defaults are examples verified in documentation, not a promise that an account can call them. A model without the required structured-output support fails safely; it is not retried with a less constrained format.

Cloud requests contain the communication fragment, selected language and relevant textual context assembled for the current request, including the partner's question and any included personal context. No audio clips or photos are sent by this sentence adapter. Patient content is transient in server memory and not logged. Review the app's sharing settings and provider terms before personal use.

Requests use fixed official endpoints (or validated loopback Ollama), block redirects, have a 1–30 second deadline, cap output generation at 2,048 tokens and response bodies at 96 KiB, honor cancellation, and avoid automatic retries. Provider error bodies are never returned. By default a device that selected an AI engine gets that engine's suggestions only: missing keys, limits, timeouts, malformed output or rejected suggestions return no choices plus an honest reason (`unavailable`, `unverified`, `device-permission`, or a detected server restart), and prepared vocabulary is shown only when the person taps **Show prepared phrases instead**. The caregiver switch **Also offer prepared vocabulary phrases with AI suggestions** restores the earlier mixed behaviour (prepared phrases fill spare slots and replace failed AI results). Health and help wording always uses prepared communication. Saving a cloud engine with no session or environment key is refused. A structured JSON response is not proof that the sentence expresses the patient's intent: grounding checks and the exact-sentence patient tap still apply.

## Cloud data and quota notes

- **OpenAI:** API data is not used for training by default. `store:false` avoids Responses application-state storage, but is not an account-wide zero-retention guarantee; standard abuse-monitoring logs may retain content for up to 30 days, with documented exceptions and eligible controls. [Data controls](https://developers.openai.com/api/docs/guides/your-data). Limits and billing depend on the project/model; a ChatGPT subscription does not establish API credit. [Rate limits](https://developers.openai.com/api/docs/guides/rate-limits), [pricing](https://openai.com/api/pricing/).
- **Anthropic:** commercial API data is not used for training by default. General retention has exceptions; structured-output documentation describes its own response handling and schema caching. Do not infer that every model/account qualifies for zero retention. Schemas contain structural definitions, not patient examples. [Retention](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data), [training](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training), [structured-output retention](https://platform.claude.com/docs/en/build-with-claude/structured-outputs). Quotas depend on account and model. [Rate limits](https://platform.claude.com/docs/en/api/rate-limits).
- **Gemini:** unpaid and paid service data terms differ. Unpaid-service terms can permit use of prompts/responses to improve products and human review, with regional/account qualifications; paid-service terms have different protections. Do not assume free quota is appropriate for personal health content. `store:false` is a request logging control, not a replacement for those terms. [Terms](https://ai.google.dev/gemini-api/terms), [API reference](https://ai.google.dev/api/generate-content). Availability, free quotas and rate limits vary. [Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits), [pricing](https://ai.google.dev/gemini-api/docs/pricing).
- **Groq:** inference content is not retained by default, but reliability/abuse investigations can retain content for up to 30 days, with legal exceptions and organization controls. Metadata is collected. Check current contractual training terms and data controls for the account instead of equating free access with private processing. [Your data](https://console.groq.com/docs/your-data), [terms](https://groq.com/terms-of-use). Free/developer limits can change and are model-specific. [Rate limits](https://console.groq.com/docs/rate-limits).

Free alternatives remain Free vocabulary and already installed local Ollama. Local inference has hardware and electricity costs; cloud promotional quotas are not guaranteed. No live paid-provider, aphasic-speech, native Tamil or clinical validation is claimed.

## Paid upgrade: ElevenLabs clone and TTS

- `POST /v1/voices/add` accepts multipart samples for Instant Voice Cloning; `DELETE /v1/voices/{voice_id}` removes a voice. Consent and a device-bound voice grant are required in Sollu. [Create IVC](https://elevenlabs.io/docs/api-reference/voices/ivc/create), [delete voice](https://elevenlabs.io/docs/api-reference/voices/delete)
- `POST /v1/text-to-speech/{voice_id}` accepts text/model and returns audio; the standard example is `mp3_44100_128`. Server uses `xi-api-key`. Validate the signed text, language, expiry and owning device before any provider call. [TTS endpoint](https://elevenlabs.io/docs/api-reference/text-to-speech/convert)
- `eleven_flash_v2_5` and `eleven_multilingual_v2` list Tamil, Hindi and English; `eleven_v3` also lists Telugu. Published request limits are 40,000, 10,000 and 5,000 characters respectively, well above Sollu's 90-character candidate cap. Vendor latency excludes application/network time. [Models](https://elevenlabs.io/docs/overview/models)
- Pricing page lists Free with 10k credits/month and Starter at US$6/month before taxes with 30k credits and Instant Voice Cloning. The free tier is not a free own-voice clone. Credit conversion varies by model/product; inspect the account's current entitlement. [Pricing](https://elevenlabs.io/pricing)
- Published general concurrency limits include Free 2 and Starter 3; Sollu's queue target is 2. Handle 429 without replaying or resurrecting a cancelled request. [429 guide](https://elevenlabs.io/docs/help-center/technical/api-error-code-429)
- TTS `enable_logging=false` is enterprise-only zero-retention mode. Ordinary history cleanup uses `DELETE /v1/history/{history_item_id}`. Identifying each generation and confirming cleanup success are live-integration checks; an unavailable ID or deletion error must never be reported as deleted. History deletion does not establish deletion from all legal/security backups. [TTS retention parameter](https://elevenlabs.io/docs/api-reference/text-to-speech/convert), [history deletion](https://elevenlabs.io/docs/api-reference/history/delete)
- ElevenLabs may use submitted data to improve models outside excluded plans; the account's Data use toggle opts future submissions out. Disable it before personal samples, record the setting and inform the voice owner. Cloning stores a reusable voice; enterprise TTS zero retention does not remove that requirement. [Training controls](https://elevenlabs.io/docs/help-center/legal/is-my-data-used-to-improve-eleven-labs-ai-models), [zero retention](https://elevenlabs.io/docs/eleven-api/resources/zero-retention-mode)

## Strict JSON schema keywords — checked 2026-09-29

The generated-sentence schema sent to OpenAI and Groq in strict mode includes `maxLength`, `maxItems` and (from 2026-09-29) `minLength: 1` on quote/text/gloss strings, matching the application's Zod validation. OpenAI's Structured Outputs guide ([developers.openai.com](https://developers.openai.com/api/docs/guides/structured-outputs)) links a supported-schemas list that could not be retrieved on this date; OpenAI's May 2025 community announcement ([Structured Outputs gets nifty improvements](https://community.openai.com/t/structured-outputs-gets-nifty-improvements/1266968)) states string lengths/formats and array min/max are supported. Groq's strict-mode keyword support was not re-verified. **Unverified with a live key:** a rejected schema would surface as `unavailable` (never as silent vocabulary) in the default AI-only mode. Run one real request per provider before relying on it. Anthropic continues to receive a schema with these bounds removed.

## Speech-to-text for Voice flow — checked 2026-09-29

**OpenAI transcription (opt-in "High accuracy").** `POST https://api.openai.com/v1/audio/transcriptions` (multipart: `file`, `model`, `language` ISO-639-1 hint `ta`/`en`, `response_format=json` → `{ text }`), per the [speech-to-text guide](https://developers.openai.com/api/docs/guides/speech-to-text): files up to 25 MB in mp3, mp4, mpeg, mpga, m4a, wav or webm. The guide now recommends a newer `gpt-transcribe` model (which takes a `languages` parameter); Sollu defaults to `gpt-4o-transcribe` with the long-standing `language` parameter and allows `OPENAI_TRANSCRIBE_MODEL` to override it. Tamil support is **not listed** in the guide and Tamil accuracy is **unverified** — no real key was available, so no live request has been made. Retention/training terms are those of the caregiver's OpenAI account and were not re-verified here.

Gates, all required: server `ALLOW_CLOUD_AI=1`; local-only media protection off; the separate caregiver switch **Allow high-accuracy transcription in Voice flow** (browser key `sollu:cloud-transcription:v1`, explicit only, fail-closed, revoked when protection is restored or the device is erased); an OpenAI key (this device's session key or `OPENAI_API_KEY`). The client rechecks permission at dispatch and sends `localOnly=false` only then. The server accepts one webm/mp4/mpeg/wav/ogg clip (≤5 MB, recordings stop at 2 minutes), keeps it only in memory for that request, never logs it, blocks redirects, caps the response at 96 KiB and returns provider errors generically. Audio is uploaded only when the person taps Stop/Send — reaching the length limit never sends automatically.

**Wispr Flow.** The [Flow API](https://api-docs.wisprflow.ai/quickstart) is "only available by exclusive access" (organization approval, dashboard-issued key; 16 kHz PCM WAV base64 input). It is **not integrated**: no approved access or verified endpoint/terms. Voice flow provides the equivalent behaviour locally (hands-free dictation, filler/stutter tidy-up that never adds words) plus the validated sentence engine and optional OpenAI transcription. A Wispr adapter can be added behind the same gates once access and documentation are available.
